# 경로 내 복잡 구간 후보 산출 알고리즘

## 목적과 경계

FirstLook은 경로에서 출발 전에 확인할 구간 후보를 뽑는다. 경로 좌표만으로 알 수 있는 것은 진행 방향의 변화와 연속성이다. 좌표만으로 실제 교차로 갈래 수, 차로 수, 고가/지상 중 어느 도로인지, 사고 위험을 판단하지 않는다.

따라서 분석기는 두 종류의 근거를 합친다.

1. **경로 기하 신호**: 급한 방향 전환과 짧은 간격의 연속 회전
2. **외부 도로/공공데이터 신호**: 복잡 교차로, 고속도로 분기점, 목적지 진입 지점, 과거 사고 이력

외부 신호는 `RouteMapFeatureSource`를 통해 출처가 붙은 `RouteMapFeature`로 제공한다. 실제 API 연결이 없는 경우 외부 후보를 만들어 내지 않는다.

## 처리 순서

1. 경로 제공자가 반환한 동일한 `RouteSnapshot`의 출처, ID, 검증된 geometry를 확인한다. curated demo 또는 geometry 미검증 경로는 분석하지 않는다.
2. geometry의 누적 거리를 계산하고 각 내부 좌표 앞뒤 35m 구간의 진행 방위각을 구한다.
3. 앞뒤 방위 차이가 35° 이상이면 방향 전환으로 표시한다. 300m 이내의 전환은 한 후보 구간으로 묶는다.
4. 후보의 복잡도는 가장 큰 회전 각도에 비례시키고, 회전 밀도는 묶인 회전 횟수에 따라 0~1로 정규화한다. 접근 좌표는 후보보다 200m 앞의 경로 위치로 둔다.
5. 외부 지도/공공데이터 feature는 route geometry에 투영한다. 경로에서 80m보다 먼 feature는 버리고, 다음 matcher에서 경로 ID·위치·방향까지 다시 확인한다.
6. `RouteAnalyzer`가 기존 가중 점수(복잡도 0.25, 회전 밀도 0.20, 분기점 0.15, 목적지 근접도 0.10, 과거 사고 신호 0.05, 로드뷰 사용성 0.10, 데이터 신뢰도 0.15)를 적용하고, 350m 경로 거리 또는 80m 좌표 거리 안의 중복을 제거해 최대 3개를 반환한다.

## 위험 정보 처리

`HISTORICAL_ACCIDENT_HOTSPOT`은 사고 이력 데이터가 제공된 경우에만 생성한다. 과거 사고 빈도는 현재 도로가 위험하다는 뜻이 아니므로 화면 문구도 “사고 이력 참고”로 제한한다. 기하상 급회전은 주의 확인 후보일 뿐 사고 위험 판정이 아니다.

## 정확한 차로 안내와 사진

이 분석기는 차로 번호, 출구 번호, 회전 지시를 생성하지 않는다. 구체적인 안내는 출처가 검증된 주행 maneuver 정보가 있고 경로 매칭 및 사진 overlay 권한까지 확인된 경우에만 별도 표시한다. Kakao Roadview의 사진 가용성은 후보의 유용도 신호로 나중에 공급할 수 있지만, 사진이 그 경로/방향/고가도로와 일치한다는 증거로 간주하지 않는다.

## 현재 한계

- 지도/공공데이터 provider는 아직 연결되어 있지 않다. 현재 자동 후보 생성은 검증된 route geometry에 있는 회전만 대상으로 한다.
- geometry의 꼭짓점 밀도와 단순화 방식이 회전 감지 결과에 영향을 준다. 공급자별 샘플 경로를 확보한 뒤 35°/35m/300m 기준을 보정해야 한다.
- 해당 알고리즘은 고가도로/지상도로 구분, 교차로 갈래 수, 도로 폭, 실시간 사고·공사·정체를 추론하지 않는다.
- `EXTERNAL_ROUTE` 분석 결과는 Pleos 주행 경로와 동일하다고 표시하면 안 된다.
