# 기능 스펙: 검증 가능한 초행길 브리핑

**기능 디렉터리**: `specs/001-firstlook-real-road-briefing/`<br>
**작성일**: 2026-11-11<br>
**상태**: 구현 진행 중<br>
**입력**: 실제 경로와 허용된 도로 사진에 연결하되, 연결이 불가능하면 Mock 시연을 안전하게 유지한다.

## 한 줄 소개

처음 가는 경로를 출발 전에 확인하려는 운전자가 경로 출처와 사진 신뢰도를 구분해 헷갈리기 쉬운 구간을 미리 살펴보는 차량용 브리핑 기능이다.

## 배경과 문제

- **대상 사용자**: 초행길의 교차로·분기점에서 차로와 방향 선택이 걱정되는 운전자
- **문제 상황**: 내비게이션의 짧은 턴 안내만으로는 복잡한 구간을 처음 마주했을 때 당황할 수 있다.
- **기존 대안의 한계**: 출발 전 거리뷰를 수동으로 찾고 여러 번 확인해야 하며, 선택한 내비게이션 경로와 사진 위치가 일치하는지 알기 어렵다.

## 차량 특화 요소

| 요소 | 내용 |
|---|---|
| 활용 데이터·기능 | Pleos 내비 경로/위치/음성 기능은 실제 프로젝트 지원이 검증된 범위에서만 사용한다. |
| 주행 맥락 | 브리핑은 출발 전 정차 상태에서 확인하고 주행 중에는 영상·키보드·복잡한 조작을 제한한다. |
| 모바일 대비 장점 | 차량의 출발 전 맥락과 큰 화면에서 목적 경로의 주요 구간을 연속해서 확인할 수 있다. |

## 심사 기준 기여

| 기준 | 기여 |
|---|---|
| 차량특화성 | 차량 출발 전과 실제 내비게이션 전환 흐름에 브리핑을 연결한다. |
| 창의성 | 목적지 도착 중심 내비에 초행 구간 사전 이해 단계를 더한다. |
| 기술 활용성 | Pleos 기능은 검증된 지원 범위에서 연동하고, 미지원 영역은 공급자 중립 계약과 Demo로 분리한다. |
| 사업성 | 초행길·복잡 구간의 불안과 반복 검색 시간을 줄이는 보조 기능을 제안한다. |

## 사용자 시나리오와 테스트

### 사용자 스토리 1 - 출발 전 구간을 미리 확인 (우선순위: P1) 🎯 시연 MVP

운전자는 수원시 영통구에서 강남역으로 가는 Demo 경로를 선택하고, 주요 구간 3개의 이미지와 설명을 확인한 뒤 완료 화면에서 Mock 주행 화면으로 이동한다. 실제 데이터와 Demo 자료의 차이는 화면에서 알아볼 수 있다.

**이 우선순위인 이유**: 외부 API 자격이나 Pleos 차량 연결이 없어도 핵심 제안 가치를 시연할 수 있다.

**단독 시연 방법**: 앱에서 목적지를 확인하고 구간별 다음/이전, 음성 설정, 완료, Mock 주행 시작을 진행한다.

**인수 시나리오**:

1. **Given** API 키와 Pleos 연결이 없는 상태, **When** Demo 경로를 선택, **Then** 3개 curated 구간과 Demo 이미지 고지를 포함해 완료까지 이동한다.
2. **Given** 차로 근거가 없는 Demo 구간, **When** 브리핑을 표시, **Then** 차로 번호·출구 순서·거리·회전 방향을 실제 안내처럼 제시하지 않는다.
3. **Given** Mock 내비게이션, **When** 주행 시작을 누름, **Then** 실제 Pleos 전환이 아닌 Mock 주행 화면임을 표시한다.

### 사용자 스토리 2 - 경로·사진 근거를 구분 (우선순위: P2)

운전자는 각 구간의 출처, 사진 종류와 촬영 정보, 경로 일치 확인 상태를 확인하고 검증되지 않은 이미지를 실제 경로 사진으로 오인하지 않는다.

**이 우선순위인 이유**: 사진의 현실성보다 실제 선택 경로와의 일치가 안전한 안내에 중요하다.

**단독 시연 방법**: Demo 자료와 미확인/사진 없음 상태를 확인한다.

**인수 시나리오**:

1. **Given** 경로 형상 또는 사진 위치 검증이 없는 경우, **When** 해당 구간을 표시, **Then** 실경로 일치 상태와 방향 오버레이를 승인하지 않는다.

### 주행 상태별 동작

| 상태 | 화면·동작 | 제한 |
|---|---|---|
| 정차 (P단) | 목적지 설정과 전체 사전 브리핑 | 외부 제공자 실제 연결은 사용권 및 프로젝트 접근 검증 뒤 활성화 |
| 주행 중 | 현재 내비게이션으로 전환하거나 Mock 주행 화면 표시 | `CarUxRestrictions` 기반으로 영상·키보드·브리핑 조작 제한; 런타임 연결 전에는 실제 제한 연동 완료로 주장하지 않음 |
| 시동 꺼짐·재개 | 현재 데모 상태를 복원 가능한 범위에서 유지 | 음성 자동 재생 금지 |

### 예외 상황

- 차량이 기능을 지원하지 않으면 Demo 모드로 남고 실제 연결이 아님을 표시한다.
- 권한, SDK 또는 네트워크가 실패하면 구체적인 안내와 Mock 재시도 경로를 제공한다.
- 사진이 없거나 날짜/heading/경로 일치가 불명확하면 실제 사진 안내와 차로별 문구를 표시하지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001**: 앱은 경로 출처를 Pleos, 외부 경로, curated Demo로 구분해야 한다.
- **FR-002**: 앱은 실제 경로 형상과 근거 데이터가 제공되지 않으면 해당 경로의 주요 구간 분석 결과를 생성하지 않아야 한다.
- **FR-003**: 앱은 한 구간에 0~3개의 사진 시점을 연결하고, 출처·콘텐츠 유형·촬영일·heading·경로 일치 상태를 제공해야 한다.
- **FR-004**: 앱은 검증되지 않은 차로, 출구 순서, 회전 방향 및 거리를 표시하거나 음성으로 읽지 않아야 한다.
- **FR-005**: 앱은 API 키나 Pleos 접근이 없어도 목적지부터 Mock 주행까지 시연 가능해야 한다.
- **FR-006**: 앱은 provider 오류·미지원·사진 없음 상태에서도 브리핑 흐름을 유지해야 한다.
- **FR-007**: 앱은 실제 내비게이션 연동 상태와 Mock 주행 상태를 구분해야 한다.
- **FR-008**: 앱은 과거 사고 데이터가 들어와도 현재 위험 판단으로 단정하지 않아야 한다.

### 핵심 데이터

- **RouteSnapshot**: 경로 식별/출처, 출발·목적지, 거리·예상시간, 선택 경로의 선택적 형상, 형상 신뢰도
- **BriefingSegment**: 유형, 이름, route offset, 선택 근거·점수, 좌표/접근점/heading의 선택값, 출처
- **RoadViewSet**: 허용된 표시 내용 0~3개, provider, 촬영일, heading, attribution, 콘텐츠 유형 및 경로 매칭 상태
- **SafetyGuidance**: 문구와 방향·차로·거리 요소별 검증 상태 및 증거 출처

## 성공 기준

- **SC-001**: Demo 경로에서 앱 재설치 직후 목적지 설정부터 완료·Mock 주행 화면까지 5단계 이내로 시연할 수 있다.
- **SC-002**: 경로/사진 일치 근거가 없는 모든 테스트 입력에서 route-verified 사진과 구체 차로·출구 안내가 0건 노출된다.
- **SC-003**: 각 구간에서 사용자에게 출처 및 Demo/실제 콘텐츠 구분이 표시된다.
- **SC-004**: 빌드 및 단위 테스트가 통과하며, 기기 검증은 Pleos 런타임 여부와 별도로 기록된다.

## 범위 밖

- 사용권 및 계정이 확인되지 않은 실제 Kakao/Naver/Google 콘텐츠를 앱에 내장하거나 저장하는 일
- NaviHelper가 공식 지원한다고 확인되지 않은 전체 경로 polyline 또는 교차로 API 가정
- 실차에서의 정확한 차로 단위 안내를 근거 없이 제공하는 일
- Pleos 실차 검증이 불가능한 환경에서 실제 차량 내비게이션 전환 완료를 주장하는 일

## 가정

- Demo 이미지는 실제 도로사진이 아닌 자체 제작 artwork로 고지한다.
- 실제 provider 키·상용 약관·Pleos 프로젝트 승인이 없으므로 기본 실행은 Demo로 한다.
- 사용자 제공 이미지와 이전 작업 트리 변경은 보존한다.
