# 기능 스펙: 승인된 실경로·도로 사진·Pleos 연동

**기능 디렉터리**: `specs/003-firstlook-live-integration/`<br>
**작성일**: 2026-11-11<br>
**상태**: 외부 접근·사용권 게이트 대기, 독립 검증 진행 중<br>
**입력**: `../001-firstlook-real-road-briefing/`과 `.omx/plans/firstlook-live-integration-roadmap.md`

## 목표

운전자가 출발 전에 확인하는 주요 구간이 실제로 선택한 Pleos 경로와 허용된 도로 사진에 근거하도록 한다. 사용권·경로 출처·위치 일치가 확인되지 않은 정보는 실제 정보로 표시하지 않으며, 핵심 데모 흐름은 계속 사용할 수 있다.

## 사용자 스토리

### 사용자 스토리 1 - 실제 선택 경로의 주요 구간 확인 (P1)

운전자는 목적지를 선택하고 Pleos 내비게이션이 확정한 같은 경로에서만 주요 구간을 확인한다.

**독립 검증**: 경로 원천과 식별자가 같은 검증 geometry·구간 후보만 승인되고, 경로가 없거나 재탐색 후 오래된 후보는 숨겨지거나 미검증으로 표시된다.

**인수 시나리오**

1. **Given** NaviHelper가 목적지 설정 및 탐색 이벤트를 제공할 때, **When** 앱이 결과를 기다리면, **Then** 요청 호출 자체를 경로 완료로 취급하지 않고 성공·취소·오류를 구분한다.
2. **Given** NaviHelper가 전체 경로 geometry를 제공하지 않거나 route ID와 후보의 출처가 다를 때, **When** 구간을 분석하면, **Then** 후보가 0개이고 외부 경로를 Pleos 경로와 같다고 표현하지 않는다.
3. **Given** 경로 재탐색 후 이전 비동기 callback이 도착할 때, **When** 화면 상태를 갱신하면, **Then** 새 route ID와 일치하지 않는 결과는 폐기된다.

### 사용자 스토리 2 - 권리가 확인된 도로 사진만 확인 (P1)

운전자는 허용된 provider가 제공한 사진, 위치·방향·촬영일 및 출처 상태를 확인한다.

**독립 검증**: 실제 API 콘텐츠 사용 권리, 시연·배포 범위, 표시·overlay·보관 조건이 문서화되기 전에는 네트워크 요청이 발생하지 않는다. 사진 없음·오래됨·방향/도로 레벨 불일치에서는 해당 사진과 구체 안내를 숨긴다.

### 사용자 스토리 3 - Pleos 기능을 사용할 수 없을 때 Demo로 완료 (P1)

사용자는 Pleos SDK 프로젝트 승인, 지도 키, 연결된 차량 없이도 목적지 설정부터 Mock 주행까지 완료한다.

**독립 검증**: SDK/provider 접근을 비활성화한 상태에서 빌드·단위 검증 및 일반 Android AVD 흐름을 확인하고, 실제 Pleos 런타임 결과와 분리해 기록한다.

## 기능 요구사항

- **FR-001**: 실제 경로는 데이터 원천, 안정된 route ID, geometry 상태 및 경로 탐색 callback 결과를 함께 가져야 한다.
- **FR-002**: 앱은 NaviHelper 요청 메서드 호출을 탐색 완료로 간주하지 않고 listener 결과를 기다려야 한다.
- **FR-003**: SDK가 반환하는 경로 요약/POI/turn-by-turn 값은 문서와 artifact에서 확인된 범위 내에서만 사용하고, 전체 polyline으로 확대 해석하지 않아야 한다.
- **FR-004**: route ID가 다르거나 geometry가 없고, 경로 변경 시점이 맞지 않거나 고가/지상 도로 레벨을 구분하지 못하면 candidate를 승인하지 않아야 한다.
- **FR-005**: 도로 사진 provider는 검색/렌더링, 촬영 메타데이터, attribution, 사용권 및 overlay 허용 여부를 구분해야 한다.
- **FR-006**: 차량 내 사용·공모전 시연·배포 권리와 API 키 정책이 확인되기 전에는 실제 provider 호출을 비활성 상태로 유지해야 한다.
- **FR-007**: 목적지 입력에 실제 좌표와 provider 식별 정보가 없으면 임의 좌표를 만들어 Pleos 목적지 요청으로 보내지 않아야 한다.
- **FR-008**: Pleos TTS, FusedLocation, Vehicle SDK, 주행 제한 연동은 프로젝트별 접근 상태와 해당 차량 runtime 지원을 각각 확인해야 한다.
- **FR-009**: 미지원·권한 오류·route mismatch·사진 없음·API 오류 시 Demo로 안전하게 되돌아가고 사용자에게 실데이터가 아님을 밝혀야 한다.
- **FR-010**: 위치, 음성, 키, project credentials를 소스와 로그에 기록하지 않아야 한다.

## 성공 기준

- **SC-001**: 경로 출처/ID 불일치, geometry 누락, 사진 누락·오래됨·반대 방향·중첩 도로 fixture에서 검증된 차로 안내가 표시되는 경우가 0건이다.
- **SC-002**: Pleos 목적지 요청과 완료/실패 상태가 테스트에서 각각 구분되고, 늦은 callback은 새 경로 화면을 변경하지 않는다.
- **SC-003**: provider 미구성 환경에서 실제 사진 요청 없이 Demo 목적지→브리핑→완료→Mock 주행 흐름이 동작한다.
- **SC-004**: Gradle assemble과 unit tests가 통과하고, 일반 Android 및 Pleos Connect emulator 증거가 별도 기록된다.
- **SC-005**: SDK 문서·artifact·프로젝트 권한·차량 runtime 상태를 혼합하지 않고 각각 근거와 확인일을 기록한다.

## 경계 및 가정

- HMG 내부/파트너 도로 사진이 공개 검색 결과에 없다는 점은 해당 데이터가 존재하지 않는다는 증거가 아니다.
- 카카오·네이버·Google 문서에 기능이 있다는 사실은 차량용 표시권을 보장하지 않는다.
- Pleos Navigation SDK가 제공하는 요약 정보는 전체 선택 경로 polyline과 동일하지 않다.
- 실제 실경로·사진 연결은 source가 확인된 뒤 별도 승인된 환경에서만 수행한다.
- 현재 baseline 앱과 Demo UX는 범위 내에서 보존한다.
